# Mografy development instructions

- Design and workflow: `docs/architecture.md`; progress: `docs/STATUS.md`; usage: `README.md`.
- Animation content belongs only in scene modules. Never add layers, keyframes, or animation data to `mografy.json`; do not introduce GSAP, SVG scene layers, or resvg.
- `packages/core/skill/` (Markdown) is the single source for scene authoring instructions, storyboard planning, and the twelve principles of animation; `packages/core/src/guide.ts` assembles it into Project AGENTS.md, shared Claude/Codex Skills, and their references. The core build generates `packages/core/src/skill-text.ts` from those files (never edit it by hand). After changing them, run `pnpm build` and `pnpm sync:skills`.
- Keep one shared Skill named `mografy` in this repository's outer `.agents/skills/mografy/` folder. Read [.agents/skills/mografy/SKILL.md](.agents/skills/mografy/SKILL.md) for product, scene, and storyboard work. Its `references/` contains project guidance, scene authoring, the sixteen built-in components, the intro example, storyboards, and animation principles. Claude's root `.claude/skills/mografy` entry links to this same folder. Never create Skill folders inside animation subprojects of this checkout (`projects/`, `examples/`); only a standalone project made by `npx mografy@latest init` from the npm package gets its own copy (`packages/cli/src/project-install.ts`).
- Keep Skill entrypoints short. Put detailed guidance in local `references/` files for both hosts. Codex storyboards use image generation; Claude storyboards use Artifacts when available, otherwise a standalone local HTML preview. Keep plans and prompts in English.
- Scene code executes only in the browser. The Server must never import or evaluate a scene in Node.
- All application writes to projects go through the queue in `packages/server/src/files.ts` and use `atomicWrite`.
- The player and exports share `@mografy/runtime`, including post-processing in `post.ts`. Changes to output effects must apply to both.
- `package.json` scripts must work under Windows `cmd` (pnpm runs scripts through it there): quote globs and paths with escaped double quotes (`--filter \"./packages/**\"`), never single quotes, which `cmd` passes through literally (`No projects matched the filters`).
- A default installation is a sparse checkout without `extras/`, `templates/`, `showreel/` and the `examples/` films other than the intro; the CLI reads those from the checkout when present and otherwise downloads them from GitHub (`packages/cli/src/github.ts`). After adding, removing or renaming files in `examples/`, run `pnpm examples:sync` and commit `examples/catalog.json`.
- After changes, run `pnpm check` (including real Chromium and FFmpeg tests) and `pnpm test:browser`; for installation or packaging changes also `pnpm test:package`. There is no CI, so these local runs are the only check, and nothing tests Windows automatically: keep the Windows `cmd` rule above in mind.
